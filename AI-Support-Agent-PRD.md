This document defines the product. It does not implement the website, the chat application, or a backend.

---

## 1. Summary

AI Support Agent is a flexible, general-purpose assistant powered by the Google Gemini API. People talk to it in a normal chat. Each person connects their own Google AI Studio API key and chooses which Gemini model answers them.

The first website this assistant is meant to support is about **self-improvement, study, and university in Britain**. A visitor might ask for a revision plan, help shaping a personal statement, a weekly routine, or a plain-language explanation of how a British university application works. The assistant is still general-purpose: it answers from the conversation, using Gemini, and it is not a fixed FAQ.

The Gemini integration must stay separate from the page design so the same assistant can later be dropped into other projects.

---

## 2. Problem

People looking for study and self-improvement guidance in a British university context usually meet one of two things: a static help page with a short list of answers, or a chat widget that only understands a handful of scripted paths. Neither handles a real conversation.

A shared company API key would also put every user’s usage, quota, and billing on one Google account. That does not scale, and it mixes one person’s questions with another person’s key.

AI Support Agent solves both issues. The conversation is open-ended and generated by Gemini. The key belongs to the person using it.

---

## 3. Goals

1. Let a person ask anything, in their own words, and continue the conversation across multiple turns.
2. Generate every reply with Gemini. The product has no catalogue of approved questions or canned answers.
3. Let the person choose among three real, currently selectable Gemini models (see section 5).
4. Require each person to supply their own Google AI Studio API key. The product never falls back to one shared key.
5. Explain, in beginner language, how to create that key and connect it.
6. Keep API keys out of source code, logs, and the public page.
7. Split the Gemini client from the user interface so another project can reuse it.
8. Publish a landing page that introduces the product, the models, the personal-key requirement, and a clear way to begin.

## 4. Out of scope for this phase

- Building the full website or the chat application.
- Implementing authentication, a database, or the Gemini client.
- Voice, image generation, live audio, or tool use.
- A shared or operator-owned Gemini key for registered users.
- Inventing model IDs for versions Google does not currently offer as selectable text models.

Later phases can add accounts, saved chats, and embedding the assistant in the Britain study site. Those are noted in section 12 so the first design does not block them.

## 5. Gemini models

Verified against Google’s Gemini API documentation on **6 November 2026**:

- [Models](https://ai.google.dev/gemini-api/docs/models)
- [Release notes](https://ai.google.dev/gemini-api/docs/changelog)
- [Deprecations](https://ai.google.dev/gemini-api/docs/deprecations)
- [Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)
- [What’s new in Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/generate-content/whats-new-gemini-3.8)
- [What’s new in Gemini 3.6 Flash and 3.5 Flash-Lite](https://ai.google.dev/gemini-api/docs/generate-content/whats-new-gemini-3.6)
- [Pricing](https://ai.google.dev/gemini-api/docs/pricing) (page last updated 30 October 2026 UTC)

Google does not currently offer three models literally named “Gemini 3.5”, “Gemini 3.6”, and “Gemini 3.8” as equal text endpoints. The request maps to the three selectable text models below. The product must use these API model IDs and no others for the picker.

### 5.1 Models the user can select

| User-facing name | API model ID | Role in the product | Status |
| --- | --- | --- | --- |
| **Gemini 3.8 Flash** | `gemini-3.8-flash` | Highest-quality choice. Google describes it as the most intelligent Flash model, aimed at long tasks, agents, and demanding workflows. | Generally available (2 September 2026). Selectable. |
| **Gemini 3.6 Flash** | `gemini-3.6-flash` | Balanced everyday choice. Previous-generation Flash model for general and agent-style tasks. | Generally available (21 July 2026). Selectable. **Default.** |
| **Gemini 3.5 Flash-Lite** | `gemini-3.5-flash-lite` | Fast, lower-cost choice for high-volume and simpler questions. This is the current selectable Gemini 3.5 text model. | Generally available (21 July 2026). Selectable. |

Shared capabilities that matter for chat, from the model pages:

- Text in, text out (these models also accept image, video, audio, and PDF; v1 of this product uses text only).
- About a 1,048,576 token input window.
- Up to 65,536 output tokens on Gemini 3.8 Flash; up to 64k on Gemini 3.6 Flash and Gemini 3.5 Flash-Lite.
- Thinking is supported. Gemini 3.8 Flash accepts thinking levels `low`, `medium`, and `high` (`minimal` returns an error). Gemini 3.5 Flash-Lite defaults to `minimal`. v1 should leave thinking at each model’s default.

### 5.2 Standard paid prices to show on the landing page

Prices are per 1 million tokens, Standard tier, from the pricing page. Free tier is available on all three. Google can change prices and free-tier quotas; the landing page must say that prices are illustrative and link to the live pricing page.

| Model ID | Input | Output (includes thinking tokens) |
| --- | --- | --- |
| `gemini-3.8-flash` | $0.75 through 31 December 2026, then $1.50 from 1 January 2027 | $3.75 through 31 December 2026, then $7.50 from 1 January 2027 |
| `gemini-3.6-flash` | $0.75 through 31 December 2026, then $1.50 from 1 January 2027 | $3.75 through 31 December 2026, then $7.50 from 1 January 2027 |
| `gemini-3.5-flash-lite` | $0.30 | $2.50 |

On the free tier, Google’s pricing table marks usage as eligible to be used to improve Google’s products. On the paid tier for these models, that column is “No”. The key guide should mention this so people can choose knowingly.

### 5.3 What must not appear in the model picker

| ID | Why it is excluded |
| --- | --- |
| `gemini-3.5-flash` | Released 19 May 2026. Deprecated. It is no longer offered for selection in Google AI Studio. Requests sent to this ID are automatically routed to `gemini-3.6-flash`. Offering it would pretend the user chose a distinct 3.5 model. |
| `gemini-3.7-flash` | Deprecated and routed to `gemini-3.8-flash`. The product request does not include 3.7. |
| Any invented ID such as `gemini-3.5`, `gemini-3.6`, or `gemini-3.8` | These strings are not the documented endpoints. |

Before implementation, re-check the models and deprecations pages. If Google retires one of the three IDs, replace that picker option with the documented successor and update the label. Do not keep a dead ID in the list.

### 5.4 How selection works

The selected model is the only model that processes that user’s messages.

- The picker stores one of the three IDs above.
- Every Gemini request for that chat sends that exact `model` value.
- Changing the model applies to the next message. Earlier turns stay in the transcript and are sent again as history, so the new model can continue the same conversation.
- The default for a new visitor is `gemini-3.6-flash`.
- The client rejects any model ID outside the allow-list.

## 6. Personal API key

### 6.1 Requirement

Every person must provide their own Google AI Studio API key before they can send a message.

- The application has no server-wide Gemini key for registered users.
- A missing, blank, or rejected key blocks chat and explains what to do next.
- Usage, quota, and billing stay on that person’s Google Cloud project.
- Two people never share a stored key.

Official references for the guide:

- [Using Gemini API keys](https://ai.google.dev/gemini-api/docs/api-key)
- [Getting started](https://aistudio.google.com/docs/get-started)
- API keys page: [https://aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey)

### 6.2 Beginner guide (copy for the product)

This is the guide the landing page and the in-app setup screen should use.

**You need your own key.** AI Support Agent does not include a shared key. Gemini runs on your Google account, and Google applies your free-tier limits or your own billing.

1. Open [Google AI Studio](https://aistudio.google.com/) and sign in with a Google account.
2. Open the API keys page: [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey).
3. Accept the terms if Google asks you to. New accounts usually receive a default project and a key after that.
4. If you do not see a key, choose **Create API key** and follow the prompt to create a key in a project. Name the project something you will recognise later, such as `ai-support-agent`.
5. Copy the key. Treat it like a password. You can return to this page later to copy it again or delete it.
6. In AI Support Agent, open **Connect your key**, paste the key, and save it.
7. Choose a model: Gemini 3.8 Flash, Gemini 3.6 Flash, or Gemini 3.5 Flash-Lite.
8. Start the conversation. Ask in your own words.

**If something fails**

- “API key not valid” means the key was copied incompletely, deleted in AI Studio, or typed with extra spaces. Create or copy it again.
- A quota or rate-limit message means this key has used its current allowance. Wait, or set up billing on that Google project. In AI Studio, billing is started from the API keys or Projects page.
- Keys created in Google AI Studio from 28 May 2026 onward are authorization keys bound to a service account and restricted to the Gemini API. That is the right kind of key for this product. You do not need to build a Google Cloud app yourself to get started.

**What the key is for**

The key lets AI Support Agent call Gemini as you. It does not give the app access to your Gmail or Drive. You can delete the key in AI Studio at any time, and you can remove it from AI Support Agent without deleting your Google account.

### 6.3 Secure handling

The browser must not call Gemini with a key baked into the page. Chat requests go to the application backend. The backend attaches that user’s key and calls the Gemini API.

| Rule | Requirement |
| --- | --- |
| No shared key | The server configuration must not contain a fallback `GEMINI_API_KEY` used for end users. |
| No key in the client bundle | The key must never appear in HTML, JavaScript source, public environment files, or analytics. |
| No key in the URL | The key is sent in a request body over HTTPS, never as a query parameter. |
| Encryption at rest | If the key is saved, store only ciphertext (AES-256-GCM or the platform’s equivalent). The encryption key lives in the server secret store, separate from the database. |
| Session option | Offer “Remember on this server” and “Use for this session only”. Session-only keys stay in server memory and are dropped when the session ends. They are not written to the database or to `localStorage`. |
| Display | After save, the interface shows a masked value (for example `•••• 7kQ2`) and a Replace / Remove action. The full key is not returned to the browser again. |
| Logs | Application logs, error trackers, and chat transcripts must redact the key. Log the model ID and a key fingerprint at most (last four characters), never the secret. |
| Transport | HTTPS only. Reject the setup form on an insecure origin. |
| Deletion | Removing the key deletes the ciphertext immediately. Later chat requests fail until a new key is saved. |
| Isolation | A key is bound to one user (or one anonymous session id before accounts exist). Request handlers load only that record. |
| XSS exposure | Because a stolen session could use a stored key, the app needs a strict content security policy, no third-party script that can read the DOM, and HttpOnly session cookies when accounts exist. |
| Validation | On save, the server makes one short Gemini request with the chosen model. Success marks the key as valid. Failure returns Google’s error in plain language and does not mark the key as saved. |

The reusable Gemini module receives the key as an argument for a single call. It does not read a global key and it does not write the key anywhere.

## 7. Assistant behaviour

### 7.1 Conversation

- A single text field and a send action. The person can type any question or any instruction.
- The interface shows the thread in order: their messages and the model’s replies.
- Each new request includes the prior turns of that conversation plus the new message, so replies can refer to what was already said.
- Replies are produced by the selected Gemini model at request time.
- There is no menu of suggested questions that limits what may be asked. Optional example prompts on an empty screen are shortcuts only; the input still accepts any text.
- Empty messages are not sent.
- While a reply is in progress, the composer shows a pending state and blocks a second send on the same thread.
- Errors from Gemini (invalid key, quota, safety block, unavailable model) appear as a short message in the thread, with the person’s text left in the composer so they can retry.

### 7.2 System instruction

The host application may pass an optional system instruction. For the Britain study website, that instruction describes the assistant’s role. It does not replace the user’s message and it does not switch the product into a scripted bot.

Suggested instruction for the first website:

> You are AI Support Agent on a website about self-improvement, study, and university in Britain. Help the person with whatever they ask. When the topic is study or university, prefer clear, practical guidance relevant to Britain (for example UCAS-style applications, personal statements, student life, and revision habits) and say when a rule depends on the university or the current official guidance. For any other topic, answer directly. Ask a short follow-up when a better answer depends on it.

Other projects replace this text. The Gemini module treats it as data.

### 7.3 What v1 chat includes

- Multi-turn text chat.
- Model picker with the three IDs in section 5.
- Personal key connection, as in section 6.
- A visible label of the model that produced the latest reply.

Streaming is desirable and can wait until the basic request/response path works. File upload, voice, and tools are later work.

## 8. Architecture for reuse

The assistant is two pieces that do not import each other.

```text
Host application (this website, or a future project)
  Landing page, chat screen, key form, model picker
        │
        │  calls
        ▼
Application backend for this product
  Sessions, encrypted key store, allow-list, redaction
        │
        │  calls
        ▼
Gemini module  (reusable library, no UI)
  send({ apiKey, modelId, messages, systemInstruction })
        │
        ▼
Google Gemini API
  model = the selected model ID
```

### 8.1 Gemini module contract

The library is the only place that knows how to speak to Gemini. Host apps depend on this contract:

```text
sendMessage(request) -> reply

request
  apiKey             string, required, used for this call only
  modelId            one of:
                       gemini-3.8-flash
                       gemini-3.6-flash
                       gemini-3.5-flash-lite
  messages           ordered list of { role: "user" | "model", text }
  systemInstruction  optional string

reply
  text               string
  modelId            the ID that actually ran
  error              absent on success; otherwise a typed code
                     (invalid_key, quota, model_unavailable, blocked, unknown)
                     plus a safe message
```

Rules for the module:

- It exports functions, not pages.
- It does not read environment variables for an end-user key.
- It does not store conversations or keys.
- It refuses model IDs outside the allow-list.
- A second host (another website, a script, a future mobile client) can call `sendMessage` with its own key source and its own system instruction.

The product backend is the adapter for this website: it owns sessions and encryption, then calls the module. A future project can skip that adapter and call the module from its own server.

### 8.2 Suggested boundaries

| Piece | Owns | Must not own |
| --- | --- | --- |
| `gemini` library | HTTP call, model allow-list, mapping Gemini errors | HTML, user accounts, key database |
| Product API | Key vault, session, chat history, request size limits | Model-specific HTTP details |
| Web UI | Landing page, chat layout, key form, model picker | Gemini URL or raw API key after save |

Chat history for this product can live in the product database, keyed by user. The library stays stateless so another project can keep history in its own store.

## 9. Landing page

### 9.1 Purpose

The landing page is the front door for the Britain-focused site and for the assistant itself. It should make four things obvious within one scroll of the hero:

1. What AI Support Agent is.
2. Why it helps with study, self-improvement, and university in Britain, while still answering freely.
3. Which Gemini models a person can choose, using the real names and IDs.
4. That they bring their own API key, plus how to get one, and a button to begin.

### 9.2 Design direction

The page should feel like a calm study, not a generic startup template.

- **Paper and ink.** Warm off-white background (`#f3efe6`), near-black text (`#1c2430`), white cards with a soft shadow.
- **Oxford blue** (`#1e3a5f`) for the header, primary buttons, and the model that is the default.
- **Copper** (`#b5683d`) as the only accent, used for small labels and the “your own key” highlight.
- **Type.** A serif for headings (Newsreader or similar) and a plain sans for body text (Source Sans 3 or similar). Generous line height. No all-caps paragraphs.
- **Layout.** One column on a phone, a simple grid of cards on a desktop. Content width about 1080px. Sections separated by space, not by heavy rules.
- **Motion.** Almost none. Buttons change background on hover. No autoplay, no chat animation that pretends the model is running.
- **Trust.** Model IDs are visible. The key section says the key stays with the user and is not a shared key. Pricing is dated and linked to Google.

### 9.3 Page structure

| Section | Content |
| --- | --- |
| Top bar | Wordmark “AI Support Agent”, links: Benefits, Models, Your key, and a **Get started** button. |
| Hero | Headline, two-sentence explanation, primary **Get started** action, secondary **See the models** action. A quiet note: built for self-improvement, study, and university in Britain, and open to any question. |
| Benefits | Four cards: ask anything, real back-and-forth, your choice of Gemini model, your own API key. |
| Models | Three cards for 3.8 Flash, 3.6 Flash (marked Default), and 3.5 Flash-Lite. Each shows the API ID, who it is for, and the standard price summary from section 5.2. A one-line note that `gemini-3.5-flash` is retired and is not offered. |
| Your key | The beginner steps from section 6.2, shortened on the page, with a link to the API keys page. A short security sentence: the key is stored encrypted for the user, or kept for the session only, and is never a shared key. |
| How a conversation works | Three steps: connect key, choose model, talk. A static sample transcript (study in Britain) marked as an example, not a live model. |
| Close | Repeat **Get started**, plus a line that the assistant can be reused in other projects because the Gemini layer is separate. |
| Footer | Product name, the verification date for model IDs (6 November 2026), and links to Google’s models and pricing pages. |

**Get started** on this concept scrolls to the key section. When the app exists, the same button opens the key connection step and then the chat.

### 9.4 Sample transcript (static)

Use this only as illustration on the landing page:

> **You:** I have four weeks until mock exams and I keep rewriting notes instead of practising. Can you give me a weekly plan?
>
> **AI Support Agent · Gemini 3.6 Flash:** Use notes only to fill gaps. Spend most of each session on exam-style questions, then review what you missed. Week 1: one subject a day, 25 minutes of questions and 10 minutes correcting them. I can turn that into a four-week timetable if you tell me your subjects.

## 10. First website context

The reusable assistant is general-purpose. The first host is a site about self-improvement, study, and university in Britain. That host:

- Uses the landing page in section 9.
- Sends the system instruction in section 7.2.
- Leaves the chat input free. Articles on the site may deep-link into chat with a draft question filled in, and the person can edit it before sending.
- Does not maintain a separate answer database for the bot.

Official rules for UCAS, visas, and individual universities change. The system instruction tells the model to say when the person should confirm details on the official source. The product does not try to be that official source.

## 11. Later reuse and later product work

When another project needs the assistant:

1. Depend on the Gemini module from section 8.
2. Supply that project’s own way of collecting a user key.
3. Pass that project’s system instruction and the same three model IDs, unless Google’s catalogue has changed.
4. Build whatever UI that project needs. The module has none.

Likely follow-on work for this product, after the PRD is accepted:

- Accounts, so a saved key and chat history survive across devices.
- Encrypted key store and the session-only alternative.
- Chat screen wired to the module.
- Streaming replies.
- A short admin note in the repo listing the allow-list and the date it was last checked against Google’s docs.

## 12. Acceptance criteria for a future build

The future build matches this PRD when all of the following are true:

1. A person can complete the key guide without a developer in the room.
2. Chat sends no message until that person’s key has been accepted.
3. No code path uses a shared Gemini key for end users.
4. The picker offers only `gemini-3.8-flash`, `gemini-3.6-flash`, and `gemini-3.5-flash-lite`.
5. A message sent with 3.8 selected is answered by `gemini-3.8-flash`, and the same is true for the other two IDs.
6. A two-message exchange shows that the second reply can use the first turn.
7. The person can ask something that is not study-related and still receive a generated answer.
8. Logs and the browser network panel (response bodies) do not contain the full API key.
9. The Gemini module can be called from a small test script that has no web UI.
10. The landing page covers the product, the benefits, the three models with their real IDs, the personal key, and a get-started path.

## 13. Risks

| Risk | Response |
| --- | --- |
| Google retires a model ID | Re-check deprecations before build and at release. Swap in the documented replacement. `gemini-3.5-flash` already shows why a stale ID is a problem. |
| Free-tier quota is tight | Say so in the key guide. Point people to billing in AI Studio. Surface quota errors in the chat. |
| A stored key leaks through logs or XSS | Follow section 6.3. Prefer session-only keys until the encrypted store and session cookie design are reviewed. |
| Prices on the landing page go stale | Date the figures and link to the official pricing page. |
| The assistant states outdated university rules | System instruction tells it to flag official sources. The site does not present model output as institutional policy. |
